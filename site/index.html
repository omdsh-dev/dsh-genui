01 — 机制

模型写的不是 Markdown，
是一份界面规格。

回复里的一段围栏，就是一份 JSON。字段决定它长成表格、图表还是测验——渲染器负责校验、修复、画出真实组件。

互动在浏览器里完成：排序、判题、拖动滑块都不发请求。需要模型参与时，一条 action 事件回到对话。

  1. 01
    围栏 模型按词汇表写出 dsh-ui JSON。
  2. 02
    渲染 宿主校验并修复规格，客户端画出组件。
  3. 03
    回流 用户操作以 action 事件回到对话。

05 — 回路

界面会说话，
模型会回应。

按钮、表单提交、排序都是本地状态；需要模型下一步时，一条带名字的事件回到对话。

  1. 01用户点击一个带 action 的按钮
  2. 02事件进入队列，本地状态先更新
  3. 03模型在新回合里读到这条事件
  4. 04新的界面替换旧的
模型收到的内容 action 
[genui-action] refresh。用户刚刚在界面中触发了动作 "refresh"，请根据组件数据执行相应操作，并用 dsh-ui 输出更新后的界面。 组件数据: {"type":"button","label":"刷新数据"}

动作名来自规格。宿主把它作为一条普通的用户消息发回对话，没有额外包装。

07 — 安装

一行命令，
装进你的 DSH。

装好后在任意对话里让模型使用 dsh-ui 围栏，或直接说「用 GenUI 画出来」。

  • 宿主DeepSeek Harness ≥ 0.2.0-rc.1
  • 运行时Node ^22.19.0 || >=24 · pnpm
  • 配置DSH web profile · corepack enable
完整安装说明 组件语法
在你的 DSH 里 
dsh plugin --profile web add @changfenhuang/dsh-genui

# 或只作为依赖安装（不会注册插件）
npm install @changfenhuang/dsh-genui
装完重启 web 宿主，围栏即刻生效。
